# Notifications — Phase 6

The signed-in Notifications module provides an in-app inbox, scheduled weekly reviews, optional morning briefings, unfinished-record deadlines, stored task reminders and exact monthly recorded-expense thresholds by currency. Review preferences before activation. Thresholds are blank until the owner chooses one. Schedules use the owner's IANA timezone; spring clock gaps advance to the first real minute, and repeated fall clock times share a date deduplication key. New activation starts now, rather than replaying earlier dates.

“Check due notifications” generates due in-app entries. The separate `pnpm notifications:run` process requires `JARVIS_NOTIFICATIONS_ENABLED=true`. It scans approximately every 30 seconds while running and can catch up at most seven days. It does not run inside a web request or start with the app. Reviews use local grounded calculations and save source-linked Assistant history; no OpenAI calls occur automatically. Deadline/reminder candidates are bounded to 200 each per scan. Weekly reviews inherit Assistant coverage limits.

Telegram delivery additionally requires explicit notification opt-in and the existing approved paired private chat. Jobs have owner-bound rule versions, deduplication keys, expiry, five-attempt retry budgets, bounded exponential/rate-limit delays and fenced leases. Source edits/completion and preference changes invalidate old queued work. Failed jobs can be explicitly retried. A crash after Telegram accepts a message but before acknowledgement can cause a duplicate: delivery is at least once, not exactly once. Pending ledger entries can represent an unknown outcome; messages include their notification ID.

Owner-scoped repositories independently authenticate web requests. The explicit worker checks the configured real owner and uses transaction-local ownership claims. All notification tables have forced RLS, compound ownership references and no browser-role access. Live schema/grants/isolation checks passed in rolled-back transactions. Automated tests cover scheduling, DST, deduplication, source invalidation, leases and retries. No real scheduled Telegram delivery has been activated or claimed verified.
